# Existing owner contract integration

The single existing StockReservationServiceClient endpoint key now registers the v2 generated client from genuine Inventory1.19. Existing URL/Platform identity propagation are reused. Remove the other three v1 registrations and their local/default/Docker config entries; no new endpoint key or production credential is required.

Exact operations require an authenticated HTTP MCP-admin principal, original bearer and one selected workspace. Capture the actual request/principal/claims/bearer/workspace/API-key permission frame once; revalidate after every owned downstream await, including exceptions and cancellation. Bound the downstream deadline to the original JWT expiry. Native Inventory independently validates its current owner mandate and authentic Cart/Order sources; a body/hash/API-key permission is never that authority.

query_stock exposes exact availability with explicit stock workspace/owner party/warehouse/Sellable. Legacy product-level/page aliases are refused. manage_reservation accepts strict generated-protobuf JSON for reserve/get/get_operation/release/bind_order/confirm; exact Cart bytes are base64-decoded without reserialization, validated against their supplied SHA, and passed unchanged. CAS and operation IDs are supplied by the caller from actual retained originals, never generated or retried locally. Expiry execution is not exposed. Responses must join the requested exact owner scope and original tuple before disclosure. Native failures remain failures, not zero stock or rollback proof.

manage_stock and manage_stock_alert retain explicit retired/unsupported responses after MCP permission checks; they have no downstream v1 client. Low-stock alerts, generic on-hand/reserved pagination and direct stock adjustments are not silently translated into exact-owned-stock writes.

The HUMAN discriminator reuses Platform HttpCurrentUser1.8 and the existing Inventory VerifiedOwnedSaleHumanCaller/VerifiedPackingActorResolver contract (authenticated unique issuer/sub plus nonblank preferred_username, excluding service-account-). This validates identity shape before calls and during current-frame checks; it creates no stock grant. The normal graph directly selects genuine Common1.2.3 to receive its automatic before-descriptor production bootstrap; no consumer vendor workaround or test serialization is added.
